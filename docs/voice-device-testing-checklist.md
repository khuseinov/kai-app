# Voice — чек-лист тестирования на устройстве

Всё, что шипнуто в сессиях 2026-06-30 → 07-02 (P0 fix → Phase 2 → Phases
A/B/C), **ни разу не проверялось на реальном железе**. Порядок блоков —
по убыванию риска: если падает блок 1, дальше можно не идти.

## Подготовка

1. HF Space пересобран с последнего `kai-hf` main (`837963e`+).
2. `.env` приложения: `VOICE_GATEWAY_BASE_URL` = URL Space (или пусто —
   через kai-core proxy), `HF_TOKEN` если Space приватный,
   `VOICE_TRANSPORT=ws` (базовый транспорт).
3. Билд на девайс: iOS — CI ipa через Sideloadly; Android — `flutter run`.
4. Держать открытым `<space>/metrics` (или `/voice/metrics`) для блока 7.

## Блок 1 — iOS mic / AVAudioSession (самый рискованный)

- [ ] Открыть /voice, тап → статус «слушаю». Говорить 15+ секунд подряд:
      волна анимируется всё время, мик НЕ глохнет после первых секунд.
- [ ] Короткая фраза (1-2 слова) → сразу тап-стоп → ответ всё равно
      приходит (flush-on-stop, P0 fix).

## Блок 2 — базовый диалог

- [ ] Вопрос голосом → голосовой ответ; до первого звука ≲5 с.
- [ ] Ответ из нескольких предложений: между клаузами нет щелчков/пауз
      (soloud continuous stream).
- [ ] Транскрипт-шторка: есть строки «you» и «kai».

## Блок 3 — barge-in

- [ ] Перебить Кая голосом во время ответа → TTS замолкает мгновенно
      (<0.5 с), начинается новый ход.

## Блок 4 — караоке (Phase B, новое)

- [ ] Во время speaking текст ответа показывается пословно: текущее слово
      подсвечено, прошлые ярче, будущие тусклее.
- [ ] Подсветка идёт примерно в такт голосу (±1 слово). Если заметно
      уезжает — зафиксировать на каком девайсе/языке: это известный флаг
      (`soloud.getPosition` на буферных стримах не проверен; есть
      wall-clock fallback).
- [ ] RU-голос: слова тоже размечены (edge-tts WordBoundary для ru), не
      равномерная «болванка».

## Блок 5 — reconnect (Phase A, новое)

- [ ] Во время сессии включить авиарежим на ~3 с и выключить → статус
      «переподключение…» → сессия восстанавливается сама (3 попытки),
      транскрипт не потерян.
- [ ] Оставить авиарежим включённым → после 3 попыток локализованная
      ошибка «связь потеряна», idle. Повторный тап после восстановления
      сети стартует чисто, без залипшей ошибки.
- [ ] Тап-стоп самим пользователем НИКОГДА не вызывает «переподключение».

## Блок 6 — interruption / маршруты

- [ ] Входящий звонок во время сессии → пауза; после звонка — авто-резюме.
- [ ] Подключить/отключить наушники (BT) в сессии → не падает, звук
      переезжает на новый маршрут.
- [ ] Свернуть/развернуть приложение во время ответа.

## Блок 7 — утечки/нагрузка

- [ ] 3 полных диалога подряд, выйти с /voice → в `/metrics`
      `voice_ws_active_sessions` = 0.
- [ ] Субъективно: нагрев/батарея в норме за ~5 минут сессии.

## Блок 8 — язык и ошибки

- [ ] Девайс на EN-локали → EN ASR/голос; на RU — RU (EN-first дефолт).
- [ ] Все тексты ошибок/статусов локализованы (нет сырого английского в
      RU-локали и наоборот).

## Блок 9 — качество звука (Opus-аплоуд)

- [ ] Распознавание не хуже, чем раньше; если появился «робот»/хрипы на
      аплоуде — зафиксировать девайс: откат = пересборка клиента без
      Opus-энкодера (сервер сам примет PCM без `?codec=opus`).

## Блок 10 — LiveKit (Phase C; требует твоих ключей LiveKit Cloud)

Активация (однократно):
1. Аккаунт на cloud.livekit.io (free tier: ~1000 агент-минут/мес) →
   создать проект → взять `wss://…` URL + API key/secret.
2. На gateway (Space secrets или локально): `LIVEKIT_ENABLED=1`,
   `LIVEKIT_URL`, `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET`.
3. Воркер на дев-машине: `cd kai/services/voice-gateway &&
   uv run --extra agent python -m src.agent.worker dev`
   (env: те же LIVEKIT_* + `KAI_CORE_URL` на Space).
4. В `.env` приложения `VOICE_TRANSPORT=livekit`, пересобрать.

Тесты:
- [ ] Диалог работает end-to-end через WebRTC (без нашего WS-пайплайна).
- [ ] **AEC acid-test**: громкий динамик, перебить Кая голосом — он
      слышит тебя сквозь собственный голос (WS так не умеет).
- [ ] Fallback: выключить `LIVEKIT_ENABLED` на сервере, перезапустить
      приложение с `VOICE_TRANSPORT=livekit` → голос молча работает
      через WS, без ошибок на экране.

## Блок 11 — web guard

- [ ] Web-сборка: кнопка микрофона в Room скрыта, прямой заход на /voice
      показывает «недоступно в браузере», без крэша.
